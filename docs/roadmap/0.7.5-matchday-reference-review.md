## Adaptation to OFMtouch

| Reference principle | OFMtouch implementation |
|---|---|
| Compact score and clock | Three-cell scoreboard; team names wrap independently; one clock |
| Combined tactical picture | Both XIs on one pitch with stable slot identity |
| Persistent current commentary | Reached latest action remains outside the history scroller |
| Separate detail cards | Statistics, lineups and player data stay in tabs |
| Dedicated tactics | Existing engine-backed decision dialog opens from one control |
| Clear temporal progression | Future events excluded from the visible stream |
| Manager breaks | Pending commands pause stepping; delayed navigation disposed on exit |

## Remaining limits

The engine exposes a ball zone, possession and discrete events; it does not currently provide continuous
player trajectories. The first pitch is explicitly labelled a tactical shape. Implementing an animated
match simulation requires an engine-to-renderer timeline, not random movement of decorative dots.
Visual viewport checks remain pending because local browser installation failed. These foundational
changes do not complete the 500-commit programme or authorise bypassing the remaining release gates.
